# md-table-align — Markdown 表格 + 盒子绘图对齐器

通用、路径无关的工具：把任意 Markdown 文件里的 **GFM 表格**和**代码围栏内的盒子绘图（ASCII art）**按**显示宽度**重新对齐，让竖线 `|` / `│` 落在相同的显示列，在等宽字体编辑器里严格对齐。

本 skill 是一个自包含单文件 `align.pyw`，支持**命令行指令**与**双击 GUI** 两种运行方式。

## 为什么需要它

### GFM 表格
只按「字符数」对齐时，中文/全角字符在编辑器里渲染为 2 个半角宽，而 ASCII 只算 1 个——算法以为对齐了，用户眼睛看到竖线却错位（"差一点"）。
本工具按**显示宽度**补空格：中文/全角记 2、其余记 1，使每个单元格占据相同的显示列宽。歧义宽度字符（弯引号 `""`、破折号 `—`、箭头 `→`、数学符号 `×÷±≥≤`、希腊字母等）按 1 计，避免被多算。

### 代码围栏内的盒子绘图（ASCII art）
许多中文技术文档的代码围栏（```）内含有 Unicode 盒子绘图（`┌│└├─` 等）混排 CJK 文字。作者画图时通常按「每个字符占 1 格」计算 padding，但 CJK 实际占 2 格宽 → 在等宽+CJK=2× 字体下右边框被撑歪、竖线错位。

本工具额外处理这类内容：检测代码围栏中同时存在盒子绘图字符与 CJK 的块，按 **│ 数量分组后组内独立做显示宽度填充**（边框线调整 ─ 数量、内容行补空格），让盒子图在各严格等宽字体下视觉对齐。

## 运行方式（双模式）

### 1. 命令行 / 指令
```bash
# 递归对齐某个目录下所有 *.md
python align.pyw E:/sEMG_B_Project

# 仅对齐指定子目录（docs/ 与 skills/）
python align.pyw E:/sEMG_B_Project docs skills

# 预演：只报告哪些文件会变化，不写回
python align.pyw E:/sEMG_B_Project --dry-run

# 对齐单个文件
python align.pyw ./README.md
```

### 2. 双击运行（GUI）
直接双击 `align.pyw` → 弹出图形界面：
- 填写/选择**路径**（目录或 .md 文件）
- （可选）填写**限定子目录**（空格分隔，如 `docs skills`）
- （可选）勾选**仅预演（dry-run）**
- 点「开始对齐」，结果明细（扫描数 / 已对齐数 / 每个文件状态）显示在下方文本框

> 双击依赖系统已将 `.pyw` 关联到 Python（`pythonw.exe`）。安装 Python 时勾选 "Associate files with Python" 即可；若未关联，可右键「打开方式」选 `pythonw.exe`，或在命令行用 `python align.pyw <路径>` 运行。

## 行为约定

- **自动排除**依赖缓存/自动生成目录：`.git`、`node_modules`、`__pycache__`、`.pio`、`vendor`、`dist`、`build`、`.workbuddy`、`venv`、`.venv` 等。
- **保留换行符**：原文件是 CRLF 还是 LF 都原样保留，不会造成整文件 diff。
- **幂等**：已对齐的文件不会被改写；二次运行写入 0 个文件，可作为对齐校验。
- **不改动内容**：
  - GFM 表格：仅调整单元格内/外的空格与分隔行，表头、单元格文本、对齐方向原样保留。
  - 盒子绘图：仅在同一 │ 数量的行之间做显示宽度补齐（边框线调 ─ 数、内容行补空格）；不动无 │ 的纯箭头/树形图；不跨组混排（避免 5 列行与 3 列行的列索引错位）。

## 处理范围

| 内容类型                                    | 所在位置                                                                                                                                                                                                        | 处理方式                       | 条件                                     |                |      |
| ------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------ | ---------------------------------------- | -------------- | ---- |
| GFM 表格 (`\       | ...\              | `) | 围栏外                                                                                                                                                                                                          | 显示宽度列对齐                 | 始终                                     |                |      |
| 盒子绘图 (`│...│`)                          | 代码围栏 (```) 内 | 按 │ 数分组 + 组内显示宽度填充 | 同时含盒子绘图字符 + CJK 且 ≥2 个 `│`/行 |                | |                                |                                          |                | |                                |                                          |                |      |

## 注意事项（重要）

对齐算法只保证**数据显示列一致**。要让用户"肉眼看到"竖线对齐，编辑器必须用**等宽且 CJK 严格 2× 宽度**的字体：

- VS Code：设 `"editor.fontFamily": "'Sarasa Fixed SC', Consolas, 'Courier New', monospace"`（等距更纱黑体，中文恰好 = 2× 英文宽）。默认 `Consolas` 无中文字形会回退到系统字体（非严格 2×），导致竖线累积漂移。
- 浏览器：默认等宽渲染即可对齐。

## 特殊内容约定

### 1. 公式 / 行内代码中的 `|` 受保护
GFM 表格拆列时会**自动忽略 `$...$`、`$$...$$`、`` `...` `` 跨度内的 `|`**，因此像附录公式表里绝对值 `$|\frac{RMS}{RMS_{trend}}-1|$` 这类写法不会被当成列分隔符劈裂。（若仍想彻底避免歧义，可把绝对值写成 `\lvert x \rvert`，源码无字面 `|` 更稳妥。）

### 2. 参考文献等长文本：用「悬挂缩进块」，不要 `|` 表格
当一行信息过长（如文献题录 + 用途 + 章节 + 代码位置），用 `|` 表格会让单元格极宽、在纯文本编辑器里无法阅读，也谈不上对齐。约定改用**无 `|` 的悬挂缩进块**：

```
**[1]** De Luca CJ. The use of surface electromyography in biomechanics[J]. *J Appl Biomech*, 1997, 13(2):135-163.
　　　具体用途：① FFT 窗口长度选择…；② EMA 平滑…
　　　引用章节：§3.1；§4.2
　　　代码位置：SignalProcessor.cpp
```

用全角空格 `　` 缩进，在 CJK=2× 等宽字体下整齐。本 skill 只对齐 `|` 块，此类块靠缩进保持整洁，运行对齐器时不会被改动。

### 3. 对齐自检（幂等）
对齐是**幂等**的：改完文档后**再跑一次** `python align.pyw <路径>`，若报告「已对齐: 0」即表示所有 `|` 表格与盒子图已严格对齐，可作为交付前的对齐校验。

## 同源维护

本 skill 的对齐算法与 `stock-daily-brief` skill 的 `scripts/lib/align-md.js`（JS 实现）**同源**。若修复对齐 bug 或调整 `disp_width`/`is_wide_cp`/`sep_cell` 逻辑，**两处必须同步更新**，否则会出现行为分叉。

> 注：盒子绘图对齐功能（`align_box_art_block`）目前仅在本 Python 版实现中可用；JS 同源版暂不含此功能（stock-brief 的 JS 对齐器仅处理 GFM 表格）。
