# 腕带系统架构
**课题名称：基于个性化自适应模型的肌电传感器疲劳预警腕带**
> 术语说明：课题名中的"模型"指基于双锚点 MDF 归一化的数学 / 生理计算模型，非机器学习模型；"个性化自适应"由本地在线自适应（Phase 1/2）与云端画像回灌（`getProfile`）实现。

> 版本：v1.0 | 更新：2026-07-13 | 合并自：固件与小程序架构.md + 云开发环境指南.md

**数据流向：**
- 固件通过 HTTP POST 将数据上传到云函数，存入云数据库（触发条件：满10帧或距上次≥3秒）
- 固件每 60 秒边界通过 HTTP POST 将分钟统计数据上传到 `uploadStats` 云函数
- 小程序通过微信云开发 `wx.cloud` API 从云数据库读取历史数据（不直连固件）
- 配网：小程序通过 BLE 将 WiFi 凭证发送给固件
- 命令：云端通过 `getDeviceCommand` 云函数下发指令，固件轮询获取（每 3 秒）
- 画像：固件启动时调用 `getProfile` 云函数获取云端纵向画像并回灌（Phase 3）

## 2. 固件端详解

### 2.1 入口: main.cpp

**setup() 执行顺序（v3.0 云方案）：**

```
1. delay(3000)                    ← 等待串口监控连接
2. Serial.begin(115200)          ← 调试串口
3. LOG("========== sEMG V3.0 CLOUD BOOT ==========")
4. 14-bit ADC 精度 + gSignal.init()
5. EEPROM.begin() + gStorage.Init()  ← 加载校准和个人信息
6. gBleConfig.init()              ← BLE 初始化（不立即广播）
7. gNetManager.initBlocking(15000)  ← WiFi连接 + DHCP + NTP阻塞同步(20s)
8. gBleConfig.setDeviceId(gNetManager.getDeviceId())  ← MAC生成deviceId后即可写入BLE
9. 注册云端回调：
   - onResetWifi / onWifiLostTimeout / onWifiReconnected
   - onRecordRelax / onRecordActive / onSaveCalib / onResetCalib
   - onProfile (Phase3 画像回灌)
10. if netOk:
      gBleConfig.stopProvisioning()
      if NTP已同步 → gNetManager.startSession()
    else:
      gBleConfig.startProvisioning()  ← BLE配网模式
      gNetManager.pauseWifiRetry()
11. gState.init() + gAppController.init()  ← 加载校准参数 → ST_RUNNING
12. 1kHz ADC Timer 初始化 + 启动   ← 校准就绪后才开始采样
13. LOG("V3.0 Cloud init complete")
```

**关键设计要点（v3.0 云方案）：**
- **Timer 在校准之后启动**：避免前几百毫秒采样数据在无校准状态下计算
- **NTP 阻塞同步**：20秒超时，同步成功后才启动 Session
- **Session ID 使用 NTP 时间戳**：格式 `sEMG_<MAC>_<秒><毫秒>`
- **WiFi 超时 15 秒**：缩短配网等待时间
- **deviceId 在 WiFi init 后立即写入 BLE**：避免配网时小程序读不到设备 ID

**loop() 主循环（10Hz, LOOP_INTERVAL_MS=100）：**

```
1. if g_adcTimerFlag:                   ← 1kHz 采样
     g_adcTimerFlag = false
     raw = FAST_ADC_READ(PIN_EMG_ADC)
     gSignal.pushSample(raw)
     gSignal.updateSampleRateStats()

2. if millis() - lastTick < 100ms: return  ← 10Hz 节拍控制

3. gBleConfig.tick()                  ← BLE 连接管理

4. _handleBleCredentials()            ← 消费 BLE 凭证 → 连接 WiFi

5. gNetManager.tick()                 ← HTTP上传 + 云端命令轮询 + WiFi 状态管理

6. gAppController.tick()               ← 核心业务调度

7. 心跳日志 (60s/次)
```

### 2.2 信号处理: SignalProcessor

> 详细算法说明（RMS/MDF/Activation/Fatigue/Quality 的完整计算公式与设计原理）请参见 [肌电算法说明文档](./肌电算法说明.md)。

**核心数据流（每 100ms 一次 update() 调用）：**

```
1. drainNewSamples() → 从环形缓冲提取新样本
2. takeSnapshotIfNeeded(256) → 从环形缓冲拷贝256点到快照缓存
3. calculateRMS() → 256点 AC 耦合（减 DC）→ sqrt(Σ(AC²)/256) → mV
4. calculateMDF() → Hanning窗 + 256点FFT → 功率谱 → findMedianFrequency(20~250Hz)
5. updateFatigue(rms, mdf) → 双锚点公式 → EMA平滑
```

**EMA 策略（MDF 平滑）：**

| 场景               | α 值          | 说明             |
| ------------------ | ------------- | ---------------- |
| 肌肉收缩中         | 0.35          | 快速跟踪频谱变化 |
| MDF 下降（疲劳趋势）| 0.35          | 加速响应         |
| 稳态连续帧 ≥10    | 0.15          | 平滑降噪         |
| 稳态未满10帧       | 0.5→0.15 渐变 | 快速初始化后稳定 |

**校准 MDF 缓冲：**
- ACTIVE 阶段每 100ms 记录一次 MDF 到 200 深环形缓冲
- finalizeCalibMdf() 计算峰值和末尾 5 点去极值均值

### 2.4 EEPROM 存储: StorageManager

**存储介质：** RA4M1 板载 Data Flash（8KB），通过 Arduino EEPROM 库访问。
云方案已移除 SPI Flash 及 A/B/C 分区架构，实时数据通过 WiFi 直接上传云端。

**EEPROM 地址布局：**

| 地址      | 大小 | 内容                    |
| --------- | ---- | ---------------------- |
| 0x00      | 32B  | WiFi SSID              |
| 0x20      | 64B  | WiFi Password           |
| 0x60      | 1B   | WiFi Magic (0xA5)       |
| 0x70      | 32B  | 校准数据 (PersonalCalibData_t) |
| 0x90      | 36B  | 用户信息 (UserProfileData_t)   |
| 0xB4      | 1B   | 校准 Magic (0xAA)      |

**校准数据结构：**

```c
PersonalCalibData_t {
  relax_rms_mv:      float    // 放松 RMS (mV)
  active_rms_mv:     float    // 收缩 RMS (mV)
  calib_timestamp_sec: uint32  // 校准时间（NTP Unix 秒）
  calib_timestamp_ms: uint16   // 校准时间（真实毫秒）
  relax_mdf_hz:      float    // 放松 MDF (Hz)
  active_mdf_hz:     float    // 收缩 MDF 峰值 (Hz)
  end_mdf_hz:        float    // 收缩末尾 MDF (Hz)
}
```

**用户信息结构：**

```c
UserProfileData_t {
  name[32]:    char     // 姓名
  age:         uint8    // 年龄
  gender:      uint8    // 1:男, 2:女
  handedness:  uint8    // 1:左手腕, 2:右手腕
}
```

### 2.7 业务调度: AppController

**tick() 调度（每 100ms）：**

```
1. signalProc.update()
2. 校准阶段处理：
   CALIB_RELAX: 10秒RMS+MDF累积 → 去极值均值 → setRelaxBaseline
   CALIB_ACTIVE: 峰值保持 → MDF缓冲 → finalizeCalibMdf → setActiveReference
3. 实时数据上传（RUNNING 态 → pushDataPoint）
4. 限频日志（正常20tick/次≈2秒，校准中10tick/次≈1秒）
5. 云端画像回灌（Phase3，设备启动后仅触发一次）
   → getProfile → _onCloudProfile → handleApplyProfile
   → 本地无校准则应用云端锚点；有则覆盖旧数据
```

**校准流程：**

| 步骤 | 命令         | 固件行为                                  | 推送         |
| ---- | ------------ | ---------------------------------------- | ------------ |
| 1    | record_relax | 启动10秒RMS+MDF累积                      | 立即ACK      |
| —    | （10秒后）  | 去极值均值→setRelaxBaseline              | 上传relax数据 |
| 2    | record_active | 启动15秒峰值保持+MDF缓冲                 | 立即ACK      |
| —    | （15秒后）  | finalizeCalibMdf→setActiveReference     | 上传active数据 |
| 3    | save_calib  | SetUserProfile→UpdatePersonalCalib→EEPROM | 上传完整校准数据 |

## 3. 小程序端详解

### 3.1 入口: app.js

**启动流程（v10.5+）：**
1. `onLaunch`: 初始化全局日志拦截 + 注入监听器
2. `onShow`: 触发统一连接流程（reset → 延迟3s → _connectDevice）
3. 优先通过 BLE 扫描获取设备最新 IP
4. BLE 失败 → 降级使用缓存 IP
5. 连接前进行 HTTP 预热（激活手机 TCP 路由表）
6. `_connectGen` 代数计数器防止过期 BLE 超时闭包逃逸
7. 监听 BLE IP 回调 → 自动 TCP 连接
8. 监听 TCP 状态变化 → 掉线 Toast 提示 + 自动重连

**连接管理集中化：** 仅 app.js 调用 `wifiClient.connect()`，所有页面只注册监听器。

### 3.2 云端通信: wx.cloud API

**小程序不直连固件**，所有交互通过云函数：

| 特性     | 说明                                       |
| -------- | ------------------------------------------ |
| 数据读取 | `wx.cloud.callFunction({ name: 'queryDataPoints' })` |

| 校准读取 | `wx.cloud.callFunction({ name: 'getCalibration' })` |

### 3.3 TabBar 页面结构

## 9. 数据库集合配置

| 集合名               | 用途                               |
| -------------------- | ---------------------------------- |
| `data_points`        | 肌电数据点（固件上传，小程序读取） |
| `devices`            | 设备注册信息                       |
| `device_commands`    | 设备命令队列（小程序写入，固件轮询）|
| `device_status`      | 设备状态上报（IP/SSID）            |
| `calibration_results` | 校准结果                           |
| `sessions`           | 会话信息（校准会话、数据会话）     |
| `stats_minutes`      | 分钟统计数据                       |

**权限设置：每个集合设为「仅创建者可写，所有人可读」**

**集合索引（可选，提升查询性能）：**

| 集合              | 索引字段                           | 用途             |
| ----------------- | ---------------------------------- | ---------------- |
| `data_points`     | `device_id`(升) + `timestamp`(降) | 按设备查历史数据 |
| `devices`         | `device_id`(升, 唯一)             | 设备去重         |
| `device_commands` | `device_id`(升) + `status`(升)     | 查待执行命令     |
| `device_status`   | `device_id`(升) + `timestamp`(降) | 查设备最新状态   |
| `sessions`        | `device_id`(升) + `started_at`(降)| 查最新会话       |
| `stats_minutes`  | `device_id`(升) + `timestamp`(降) | 查统计数据       |

> 首次调用云函数时会尝试自动创建集合，但权限仍需手动设置。

## 11. 常见问题

### Q1: 找不到"云开发"按钮？
确保 `project.config.json` 中有 `cloudfunctionRoot` 配置，微信开发者工具版本 >= 1.02。

### Q2: 部署失败，提示"缺少 config.json"？
确保每个云函数目录都有 `config.json` 文件（脚本部署时会自动检查）。

### Q3: 权限设置后小程序仍无法读取数据？
- 权限是否设为 **「仅创建者可写，所有人可读」**（不是「仅创建者可读写」）
- 小程序是否调用了 `wx.cloud.init({ env: 'cloud1-d4gqmimmo05b12c94' })`

### Q4: 固件调用云函数返回 404 / INVALID_PATH？
分两种情况：
- **响应体含 `{"code":"INVALID_PATH",...}`**：请求已打到 CloudBase 网关，但该路径没在「HTTP 访问服务」登记。
  修复：控制台 → **「HTTP 访问服务」**（独立菜单，不在函数详情页里）→ 新建访问路径 → 关联函数、路径填 `/<函数名>` → 保存 → 重启设备。
- **固件日志只显示 HTTP error 无结构化 body**：多为请求方法/连接问题，固件所有云端调用统一走 **POST**。

> 经验法则：**每新增一个固件 HTTP 调用的云函数，除了上传部署，必须额外在「HTTP 访问服务」登记同名路径**，否则一律 `INVALID_PATH`。

### Q5: 固件无法连接云端？
1. 检查固件 WiFi 是否已连接（串口日志 `[NET] WiFi connected`）
2. 检查云函数 HTTP 触发器是否已开启
3. 确认固件中 `CLOUD_BASE_DOMAIN` 与云开发控制台的 HTTP 访问服务域名一致
