**数据流向：**
- 固件每 1 秒通过 HTTP POST 将 10 帧数据上传到 `dataIngest` 云函数，存入云数据库

## 2. 固件端详解

### 2.1 入口: main.cpp

**setup() 执行顺序（v2.2.0）：**

```
1. delay(3000)                    ← 等待串口监控连接
2. Serial.begin(115200)          ← 调试串口
3. LOG("========== sEMG V3.0 CLOUD BOOT ==========")
4. 14-bit ADC 精度 + gSignal.init()
5. EEPROM.begin() + gStorage.Init()  ← 加载校准和个人信息
6. gBleConfig.init()              ← BLE 初始化（不立即广播）
7. gNetManager.initBlocking(15000)  ← WiFi连接 + DHCP + NTP阻塞同步(20s)
   └─ netOk → setDeviceId → stopProvisioning → startSession(NTP时间戳+毫秒)
8. gState.init() + gAppController.init()  ← 加载校准参数 → setCalibration → ST_RUNNING
9. 1kHz ADC Timer 初始化 + 启动   ← 校准就绪后才开始采样
10. LOG("V3.0 Cloud init complete")
```

**关键设计要点（v2.2.0）：**
- **Timer 在校准之后启动**：避免前几百毫秒采样数据在无校准状态下计算
- **NTP 阻塞同步**：20秒超时，同步成功后才启动 Session 和 Timer
- **Session ID 使用 NTP 时间戳**：格式 `sEMG_<MAC>_<秒><毫秒>`（如 `sEMG_F0F5BD52EED8_1783317880036`）
- **WiFi 超时 15 秒**：缩短配网等待时间

**loop() 主循环（10Hz, LOOP_INTERVAL_MS=100）：**

```
if g_adcTimerFlag:
  g_adcTimerFlag = false
  raw = FAST_ADC_READ(PIN_EMG_ADC)  ← 双读清管道
  gSignal.isrPushSample(raw)        ← 推入512深环形缓冲
  gSignal.updateSampleRateStats()   ← 采样率统计

if millis() - lastTick < 100ms: return  ← 10Hz 节拍控制

gBleConfig.tick()              ← BLE 连接管理
_handleBleCredentials()        ← 消费 BLE 凭证 → 连接 WiFi
gNetManager.tick()             ← HTTP上传 + 云端命令轮询 + WiFi 状态管理
gAppController.tick()          ← 核心业务调度
```

### 2.2 信号处理: SignalProcessor

> 📖 详细算法说明（RMS/MDF/Activation/Fatigue/Quality 的完整计算公式与设计原理）请参见 [肌电算法说明文档](./肌电算法说明.md)。

**核心数据流（每 100ms 一次 update() 调用）：**

```
1. drainNewSamples() → 从环形缓冲提取新样本
2. takeSnapshotIfNeeded(256) → 从环形缓冲拷贝256点到快照缓存
   - DC偏置：简单均值估计
3. calculateRMS()
   - 256点 AC 耦合（减 DC）
   - RMS = sqrt(Σ(AC²)/256)
   - 输出单位：mV（通过 m_mvPerAdcUnit 转换）
4. calculateMDF()
   - takeSnapshot → calculatePowerSpectrum()
   - Hanning 窗加权
   - 256点 FFT（Cooley-Tukey 自实现，bitReverse + 迭代蝶形）
   - 功率谱 = (real²+imag²)/N
   - findMedianFrequency(10~250Hz)：累积功率过半处
   - EMA 平滑（α 自适应 0.15~0.35）
5. updateFatigue(rms, mdf)
   - 激活度：A = (rms-relax_rms)/(active_rms-relax_rms)，clamp [0,1]
   - 收缩检测：双阈值系统（rms > relax_rms×2 且 rms > max(active_rms×0.3, 10mV)），动态阈值自动适应用户个体差异，移除MDF条件避免天花板效应
   - 疲劳度：F = (activeMDF-mdf)/(activeMDF-relaxMDF)×100，EMA(α=0.1)
   - 收缩门控：仅收缩中计算，放松时疲劳度保持不变（肌肉疲劳恢复需要数分钟到数十分钟）
   - 锚点来源：校准阶段记录的 active_mdf_hz 和 relax_mdf_hz
   - 预计算范围：mdfRange = activeMDF - relaxMDF，避免重复计算
```

**EMA 策略（MDF 平滑）：**

| 场景 | α 值 | 说明 |
|------|------|------|
| 肌肉收缩中 | 0.35 | 快速跟踪频谱变化 |
| MDF 下降（疲劳趋势） | 0.35 | 加速响应 |
| 稳态连续帧 ≥10 | 0.15 | 平滑降噪 |
| 稳态未满10帧 | 0.5→0.15 渐变 | 快速初始化后稳定 |

**MDF 有效性判断：**
- rawMDF 在 [10, 250] Hz 范围内 → 生理有效
- rawMDF 在 [8, 10) Hz → 可接受但质量较低
- 异常帧：保持上次有效值，不更新 EMA

**校准 MDF 缓冲（v3.9.24）：**
- ACTIVE 阶段每 100ms 记录一次 MDF 到 200 深环形缓冲
- finalizeCalibMdf() 计算峰值和末尾 5 点去极值均值

### 2.4 EEPROM 存储: StorageManager

**存储介质：** RA4M1 板载 Data Flash（8KB），通过 Arduino EEPROM 库访问。
云方案已移除 SPI Flash 及 A/B/C 分区架构，实时数据通过 WiFi 直接上传云端。

**EEPROM 地址布局：**

```
0x00 ──────── 32B ── WiFi SSID
0x20 ──────── 64B ── WiFi Password
0x60 ──────── 1B  ── WiFi Magic (0xA5)
0x70 ──────── 32B ── 校准数据 (PersonalCalibData_t，代码注释标注32B，实际结构体26B)
0x90 ──────── 36B ── 用户信息 (UserProfileData_t，代码注释标注36B，实际结构体35B)
0xB3 ──────── 1B  ── Profile Magic (0xBB，位于 PROFILE_ADDR + sizeof(UserProfileData_t))
0xB4 ──────── 1B  ── 校准 Magic (0xAA)
```

**校准数据结构（32 字节）：**

```c
PersonalCalibData_t {
  relax_rms_mv:      float    // 放松 RMS (mV)
  active_rms_mv:     float    // 收缩 RMS (mV)
  calib_timestamp_sec: uint32 // 校准时间（NTP Unix 秒）
  calib_timestamp_ms: uint16  // 校准时间（真实毫秒）
  relax_mdf_hz:      float    // 放松 MDF (Hz)
  active_mdf_hz:     float    // 收缩 MDF 峰值 (Hz)
  end_mdf_hz:        float    // 收缩末尾 MDF (Hz)
}
```

**用户信息结构（35 字节）：**

```c
UserProfileData_t {
  name[32]:    char     // 姓名
  age:         uint8    // 年龄
  gender:      uint8    // 1:男, 2:女
  handedness:  uint8    // 1:左手腕, 2:右手腕
}
```

**数据权威性：** EEPROM 为唯一权威数据源，小程序 localStorage 仅作快照缓存用于快速 UI 展示。

**校准数据验证：**
- Magic 字节检查（0xAA）
- NaN 检测（所有 float 字段合理性检查）

**关键 API：**

| 函数 | 说明 |
|------|------|
| `Init()` | 初始化 EEPROM，打印校准有效状态 |
| `GetPersonalCalib(data)` | 读取校准数据（含 NaN 校验） |
| `UpdatePersonalCalib(data)` | 保存校准数据（含 NaN 防御） |
| `GetUserProfile(profile)` | 读取用户信息 |
| `SetUserProfile(profile)` | 保存用户信息 |
| `LoadWifiCredentials(creds)` | 读取 WiFi 凭证 |
| `SaveWifiCredentials(creds)` | 保存 WiFi 凭证 |
| `tick()` | 空函数（云方案无本地存储轮询） |

**EEPROM 特性：**
- 总容量：8 KB
- 写入方式：EEPROM.update()（仅变化时写入，减少磨损）
- 擦写寿命：> 100,000 次

### 2.5 网络通信: NetManager（云端 HTTP 上传方案）

**架构：** 固件通过 HTTP POST 将数据上传到微信云开发云函数，不再使用 WebSocket 直连小程序。

```
固件 ──HTTP POST──► 微信云函数(dataIngest) ──► 云数据库
固件 ──HTTP POST──► 微信云函数(uploadStats) ──► 云数据库
小程序 ──云函数调用──► 云数据库 ← 读取固件上传的数据
```

**上传格式（v2.2.0，真实物理值）：**

```json
{
  "points": [
    [1783317880, 885, 4.281, 100.0, 49.0, 6.5, 80],
    [1783317880, 985, 4.320, 98.5, 48.8, 6.7, 80],
    ...
  ]
}
```

字段顺序固定：`[timestamp_sec, ms, rms, activation, mdf, fatigue, quality]`

| 字段 | 说明 | 单位 |
|------|------|------|
| timestamp_sec | NTP 同步后的 Unix 秒 | 秒 |
| ms | 真实毫秒（(millis()-ntpBaseMs)%1000） | 毫秒 |
| rms | 肌电均方根 | mV |
| activation | 激活度 | % |
| mdf | 中位频率 | Hz |
| fatigue | 疲劳度 | % |
| quality | 信号质量 | 0-100 |

**上传参数（v2.2.0）：**

| 常量 | 值 | 说明 |
|------|-----|----------|
| `INGEST_BATCH_FRAMES` | 10 | 每批上传帧数（1秒 @ 10Hz） |
| `INGEST_RETRY_QUEUE` | 150 | 断网重试队列最大帧数（15秒缓存） |
| 上传频率 | 1秒/次（缓冲区满触发） | 实时性约 1 秒延迟 |

**上传触发条件：**
- 缓冲区满：`_batchCount >= INGEST_BATCH_FRAMES`（10帧）

**断网重试机制：**
- `pushDataPoint()` 先将数据存入 `_retryQueue`（150帧环形缓冲）
- 网络恢复后，下次成功上传时会将重试队列中的数据补传到云端
- 队列满时覆盖最旧数据（环形覆盖）

**分钟统计（v2.2.0）：**
- 固件累积每分钟的统计数据（rms_avg, rms_max, rms_min, mdf_avg, mdf_max, fatigue_avg, fatigue_max, quality_avg, sample_count）
- 每分钟边界触发上传到 `uploadStats` 云函数

**云端通信链路：**

| 功能 | 云函数 | HTTP 路径 |
|------|--------|----------|
| 设备注册 | `deviceRegister` | `/deviceRegister` |
| 数据上传 | `dataIngest` | `/dataIngest` |
| 分钟统计 | `uploadStats` | `/uploadStats` |
| 校准上传 | `uploadCalibration` | `/uploadCalibration` |
| 命令拉取 | `getDeviceCommand` | `/getDeviceCommand` |
| 状态上报 | `reportDeviceStatus` | `/reportDeviceStatus` |
| 命令确认 | `ackDeviceCommand` | `/ackDeviceCommand` |

**HTTP 实现：**
- 使用 `WiFiClient` + `client.print()` 手动构造 HTTP POST 请求
- 目标：绕过 UNO R4 WiFi 的 HTTPS 兼容性问题（改用 HTTP）
- 云端 Base URL：`http://cloud1-d4gqmimmo05b12c94-1446329561.ap-shanghai.app.tcloudbase.com`

**NTP 时间同步（v2.2.0）：**

| 特性 | 说明 |
|------|------|
| 服务器 | ntp.aliyun.com（固定 IP 203.107.6.88，避免 DNS 查询导致 hardfault） |
| 同步方式 | 阻塞等待（20秒超时），成功后才启动 Session 和 Timer |
| 后台重试 | 阻塞失败后，前3次 5秒间隔，之后 30秒间隔 |
| 时间精度 | 毫秒级（(millis()-ntpBaseMs)%1000） |
| NTP未同步 | pushDataPoint 返回 false，跳过上传 |

**Session ID 格式（v2.2.0）：**
```
sEMG_<MAC>_<Unix秒><毫秒>
例如：sEMG_F0F5BD52EED8_1783317880036
```

### 2.6 BLE 配网: BleConfigServer

| 参数 | 值 |
|------|-----|
| Service UUID | 19B10000-e8f2-537e-4f6c-d104768a1214 |
| SSID Char | 19B10001（Write/Notify, 32B） |
| Device ID Char | 19B10002（Read/Notify, 32B） |
| IP Address Char | 19B10003（Read/Notify, 128B） |
| Password Char | 19B10004（Write/Notify, 64B） |

**配网流程：**
1. 固件上电 → BLE 广播（名称 "sEMG_xxxx"）
2. 小程序扫描连接 → 发送 SSID(19B10001) + Password(19B10004)
3. 固件收到 → 保存到 EEPROM → 切换 WiFi STA → 连接路由器
4. DHCP 获取 IP → 更新 IP Char(19B10003)
5. 配网完成 → 固件自动连接 WiFi

**BLE 广播重启（v3.9.39）：**
WiFi 连接成功后，`resumeAdvertising()` 会先 `BLE.stopAdvertise()` 再 `BLE.advertise()`，确保广播干净重启，避免 ArduinoBLE 库在已广播状态下重复调用 `advertise()` 导致广播被意外停止。

### 2.7 业务调度: AppController

**tick() 调度（每 100ms 执行一次）：**

```
1. signalProc.update() → 获取最新 RMS/MDF/Fatigue/Activation/Quality
2. 校准阶段处理：
   CALIB_RELAX:
     - RMS+MDF 累积（含 min/max 追踪）
     - 10秒到期 → 去极值均值 → setRelaxBaseline() → 上传 relax 阶段结果
   CALIB_ACTIVE:
     - 峰值 RMS 保持
     - recordCalibMdf() 记录每帧 MDF
     - 15秒到期 → finalizeCalibMdf() → setActiveReference() → 上传 active 阶段结果
3. 实时数据上传（RUNNING 态 → pushDataPoint）
4. 限频日志（正常运行 20 tick/次 ≈ 2秒，校准中 10 tick/次 ≈ 1秒）
```

**校准流程（handleRecordRelax / handleRecordActive）：**

| 步骤 | 命令 | 固件行为 | 推送 |
|------|------|---------|------|
| 1 | record_relax | 启动 10 秒 RMS+MDF 累积 | 立即 ACK |
| — | （10秒后） | 去极值均值 → setRelaxBaseline | 上传 relax 阶段数据 |
| 2 | record_active | 启动 15 秒峰值保持 + MDF 缓冲 | 立即 ACK |
| — | （15秒后） | finalizeCalibMdf → setActiveReference | 上传 active 阶段数据 |
| 3 | save_calib | SetUserProfile → UpdatePersonalCalib → 写入 EEPROM | 上传完整校准数据 |

**save_calib 命令参数（v2.2.0）：**
- 包含 params 字段：`{name, age, gender, handedness}`
- 用户信息在 params 中传递，固件解析后写入 EEPROM

**个人信息持久化流程：**
1. 用户填写 profile 表单 → 小程序发送 `save_calib{name,age,gender,handedness}`
2. 固件解析 params → `SetUserProfile()` → 个人信息写入 EEPROM
3. 小程序 localStorage 同步更新（作为快照缓存，EEPROM 为权威数据源）

**启动日志输出（v2.2.0）：**

```
[CTRL] Boot: loaded calib relax_rms=4.281 active_rms=250.420 relax_mdf=49.5 active_mdf=165.5 end_mdf=132.4
[CTRL] Boot: loaded profile name=test age=45 gender=male hand=left
[SIG] Relax baseline set: rms=4.281, mdf=49.5
[STATE] BOOT -> RUNNING
```

## 3. 小程序端详解

### 3.1 入口: app.js

**启动流程（v10.5）：**
1. `onLaunch`: 初始化全局日志拦截 + 注入监听器（**不**发起连接）
2. `onShow`: 触发统一连接流程（reset → 延迟3s → _connectDevice(true)）
3. 优先通过 BLE 扫描获取设备最新 IP
4. BLE 失败 → 降级使用缓存 IP（wx.storage device_ip）
5. 连接前进行**网络预热**：通过 `wx.request` 发 HTTP 请求到目标 IP 激活手机 TCP 路由表（v10.8）
6. `_connectGen` 代数计数器防止过期 BLE 超时闭包逃逸（v10.5）
7. 监听 BLE IP 回调 → 自动 TCP 连接
8. 监听 TCP 状态变化 → 掉线 Toast 提示 + 自动重连

**连接管理（集中化）（v10.4）：**
- **仅 app.js 调用 `wifiClient.connect()`**，所有页面只注册监听器
- 页面 onShow 不自行发起连接，由 app.onShow 统一管理
- 避免网络请求冲突，使用队列管理重连

**onShow 重连流程（v10.3）：**
```
wifiClient.reset()           ← 取消所有旧重连定时器，挂起重连
→ 3 秒延迟                   ← 等待手机 WiFi 路由恢复
→ _connectDevice(true)       ← force=true 跳过防抖
→ BLE 扫描 → 拿到 IP
→ HTTP 预热（v10.8）         ← 强制内核建立 ARP + 路由
→ 云端连接
```

**全局数据模式：**
- `app.dataMode`: 'idle' | 'streaming'
- 页面切换时自动停止数据流（setDataMode）

### 3.2 云端通信: 云函数调用

**架构：** 小程序不直接连接固件，而是通过微信云函数读取固件上传到云端的数据。

| 特性 | 说明 |
|------|------|
| 数据上传 | 固件通过 HTTP POST 发送到 `dataIngest` 云函数 |
| 数据读取 | 小程序调用 `queryDataPoints` 云函数从云数据库查询 |
| 命令下发 | 小程序调用 `sendDeviceCommand` 云函数，固件轮询 `getDeviceCommand` |
| 实时性 | 固件 1 秒上传一次，小程序查询延迟约 1~3 秒 |

**相关云函数：**

| 云函数 | 功能 | 调用方 |
|--------|------|--------|
| `dataIngest` | 接收固件数据并存入云数据库 | 固件 |
| `deviceRegister` | 设备注册 | 固件 |
| `getDeviceCommand` | 拉取待执行命令 | 固件 |
| `reportDeviceStatus` | 上报设备状态 | 固件 |
| `uploadStats` | 接收分钟统计数据 | 固件 |
| `uploadCalibration` | 接收校准数据 | 固件 |
| `getDeviceStatus` | 查询设备状态 | 小程序 |
| `sendDeviceCommand` | 下发命令给固件 | 小程序 |
| `ackDeviceCommand` | 确认命令已执行 | 固件 |
| `queryDataPoints` | 查询历史数据（含聚合统计和导出） | 小程序 |
| `cleanupOldData` | 清理过期数据（每日 2:00） | 定时触发器 |

> **注意：** 云方案下，小程序与固件之间不再有直接的 WebSocket 连接。`wifiClient.js` 在云方案版本中已不再使用。

### 3.3 通信模块: bleClient.js

**BLE 客户端（V2.3.0）：**

| 特性 | 说明 |
|------|------|
| 扫描 | 前缀 "sEMG_"，15s 超时，选择 RSSI 最强设备 |
| MTU | 协商 247 字节 |
| Notify | 监听 IP Address Char(19B10003) |
| 粘包处理 | 缓冲 + {} 检测 + 超时强制解析 |
| 兼容性 | 兼容 {ip:"..."} 和 {status:"ok",ip:"..."} 格式 |

**配网发送：**
1. 写 SSID → 19B10001
2. 延迟 150ms → 写 Password → 19B10004

### 3.4 本地存储: storage.js

**单用户设计。localStorage 作为快照缓存（快速 UI 展示），固件 EEPROM 为唯一权威数据源。**

| Key | 内容 | 权威源 |
|-----|------|--------|
| current_user | 当前用户对象 {name, gender, age, handedness, relax_rms, active_rms} | EEPROM |
| user_profile | 用户 profile 备份（与 current_user 同步） | EEPROM |
| calib_data | 校准结果缓存 {relax_rms, active_rms} | EEPROM |
| device_ip | 设备 IP 地址 | BLE 回传 |
| cloud_url | 云函数 Base URL | 本地配置 |
| device_ssid | 已连接 WiFi SSID | BLE 回传 |

**数据流向：**
```
用户输入 → 小程序 localStorage (快照缓存)
         → save_calib{profile} → 固件 EEPROM (权威源)
         
页面加载 ← 小程序 localStorage (快速读，不查固件)
         (如缓存丢失，需重新配网+校准恢复)
```

**API：**
- getCurrentUser() — 读取 current_user
- setCurrentUser(user) — 写入 current_user
- saveCurrentUser(user) — 同时写入 user_profile + current_user
- loadUserProfile() — 读取 user_profile
- clearUserProfile() — 清除所有用户数据
