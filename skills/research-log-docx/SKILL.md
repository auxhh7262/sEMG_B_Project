# research-log-docx — 研究日志 Markdown → Word 转换

本 skill 把项目里的《研究日志.md》转换成排版与 `_org.docx` **逐页一致**的 Word 文档，用于「更新 md 后重新生成 word」的重复任务。它把该文档从 Markdown 到 Word 的**全部生成规则（页面 / 分页 / 表格 / 字体 / 抑制项）**写死在脚本里，保证后续每次重新生成都和原始 org 版本长相一致。

> 验证口径：用 LibreOffice 把生成 docx 与 `_org.docx` 都转 PDF，逐页做像素差 + 单元格级对齐/字体/字号/加粗全量比对。
> 字体/字号/对齐在**有内容单元格上与 org 一致**；但**两处按用户偏好刻意偏离 org**（见「与 org 的已知差异」）：① 日志表数据行 时间/操作/字数 三列**不加粗**（org 原为加粗）；② 次数统计表整表**居中**（org 原表头/标签行左对齐、仅末行居中）。
> 生成文档 = **86 页**，org = **87 页**；当前 md 比 org 基线内容略多（日志持续更新）＋ LibreOffice 用替代字体渲染宋体，故前几页像素差稍高（avg≈3.9，且 0 页差异>20），余页贴近，均非排版 bug。加粗仅剩：封面标题、`###` 二级目录；导航窗格一/二级与 org 完全一致。

## 文件结构

```
skills/research-log-docx/
├── SKILL.md                       # 本说明
└── md_to_research_log_docx.pyw    # 转换器（python-docx，无控制台；双击即按默认路径生成）
```
> 转换器**自包含、零外部资源**：时间分布（按周/按月）柱状图由 `md_to_research_log_docx.pyw` 内的
> `parse_weekly_table()` + `build_weekly_chart_png()` 从 md 表格**实时解析并生成**（matplotlib +
> SarasaFixedSC 中文等宽字体），不再打包任何静态 PNG / 生成脚本。图表数据与 md 表格永远一致。

## 固化的「生成要求 / 排版规则」

转换严格遵循以下规则（即 org 是怎么从 md 变出来的）：

### 1. 页面
- A4（11900×16840 twips）；页边距 上860 / 下1120 / 左740 / 右460 twips
  （≈ 上1.52 / 下1.98 / 左1.31 / 右0.81 cm）；页眉距601、页脚距921 twips。
- **org 不带任何页眉/页脚、无页码**。生成文件也严禁加页码（早期版本误加 PAGE 域会导致整体错位）。

### 2. 默认字体与行距（最易踩坑）
- 正文 **宋体、10.5pt（sz=21）**；单元格同字号（org 实测表格单元格均为 10.5pt）。
  ⚠️ **org 并非所有单元格加粗**——加粗仅出现在：① 封面标题（宋体 20.5pt 加粗；
  org 标题不显式设字体、继承 Normal 默认=宋体，故生成文档也用宋体，避免首页标题字体与正文内容不一致）；
  ② `###` 二级目录（宋体 10.5pt 加粗）。
  ⚠️ **日志表数据行 时间/操作/字数 三列（c0/c1/c3）按用户偏好不加粗**（org 原本对这 3 列加粗，
  此为 2026-07-28 用户明确要求后的刻意偏离）。其余（封面字段、一级标题 `##`、日志表全部单元格、
  分布表、周分布表、明细表）**一律不加粗**。早期误把“表格全加粗”导致与 org 不一致——现已修正为上述规则。
- **行距 = 自然单倍（natural single）**。python-docx 默认模板的 `docDefaults/pPrDefault/w:spacing`
  带了 `w:after="200" w:line="276" w:lineRule="auto"`（段后 200twips ＋ 1.15 倍行距），会让**每个段落、
  尤其是每个表格单元格**下方多出 200twips 空白，是「所有表格变高、整文档多 4 页」的**头号元凶**。
  → 生成时必须调用 `neutralize_doc_defaults()`：把 `w:after` 设 0，并**删除** `w:line`/`w:lineRule`
  （让其回到与 org 一致的自然单倍），不能留 `line=276`。

### 3. 标题（Markdown 一级 `#`）
- 取 `#` 文本作为主标题，**强制分两行**：第一行为主标题文本，第二行为「研究日志」。两行均为**宋体**（org 封面标题不显式设字体、继承 Normal 默认=宋体，
  与正文内容字体一致；**切勿用 Microsoft JhengHei**，否则首页标题字体与正文内容不一致）、加粗、20.5pt（sz=41）、居中。
- 主标题行左右缩进设为 500 twips（原 org 为 2619，因主标题较长需缩小缩进确保一行显示）；行距 `line=536`（EXACTLY）。
- 通过 `p.add_run().add_break()` 在主标题与「研究日志」之间插入强制换行，确保「研究日志」独占第二行。
- 封面标题用 `space_before = 3080 twips` 推到页面中上部（对齐 org 由若干空段落下推后的视觉位置），
  **不要插入空段落**。

### 4. 封面信息块（`#` 与第一个 `##` 之间的 `**字段：** 值` 行）
- 整体居中、宋体 9.5pt（sz=19）、颜色 `2D2D2D`、**不加粗**（org 实测封面字段不加粗；源 `**` 仅作标记，转换后去除且不保留加粗）。
- **所有六行信息使用统一的间隔模式**（用户偏好：间隔相等）：
  - 所有信息行 `space_before=0`、`line=None`（默认单倍行距，**不设 2.5 倍行距**）。
  - 每两行之间插入一个空段落，空段落 `space_before=10 twips`，形成统一的视觉间隔（≈空行行高 + 10 twips）。
  - 标题→学校之间同样使用空段落（`space_before=10`）撑开，与后续间隔一致。
  - 缩进：学校 `left=2613`，其余 `left=2619`，右缩进均 `2612`。
- ⚠️ **行距必须显式清除**：`set_paragraph_format` 在 `line=None` 时需删除 XML 中的 `w:line`/`w:lineRule` 属性，
  否则会继承默认样式中的行距设置（如 2.5 倍行距），导致作者/指导老师行间距与其他行不一致。
- 封面信息块字段顺序固定为 学校→作者→指导老师→创建时间→日志首次提交时间→日志最终提交时间。
- 源中的 `---` 分隔线直接丢弃。

### 5. 章节标题（Markdown 二级 `##`）
- **宋体、13pt、加粗**（注意：原 org 用微软正黑体，但该字体顿号"、"字形居中不符合中文排版习惯，故改为宋体加粗；加粗后笔画更醒目，与正文形成层次对比）；应用 Word「标题 1」样式（pStyle=1，即导航窗格"一级"）以对齐 org，但必须先把生成文档的
  「标题 1」样式 `space_before/after` 归 0、字号设 26（13pt），否则非首个 `##` 会继承默认 480twips
  段前而下沉。
- 第一个 `##` 额外带左缩进 1021 twips + 段前 53 twips；其余 `##` 段前设 0（其前必有分页符）、行高 376 twips。

### 6. 子条目（Markdown 三级 `###`，如「1、提出主题」）
- 宋体、加粗、**10.5pt**，与正文同字号（仅靠加粗区分），**不使用标题样式**；去掉末尾句号。
  ⚠️ **导航窗格“二级”靠 `w:outlineLvl=1` 实现**：`###` 段落不套用标题样式，而是设置
  `w:pPr/w:outlineLvl/@w:val="1"`，org 据此把二级目录纳入导航窗格（org 导航窗格含一、二级）。
  漏设则导航窗格缺二级目录。

### 7. 分页规则（与 org 完全一致，共 79 个分页符）
- **每个 `##` 之前都插入分页符**（含封面→正文第一个 `##`）。org 共 3 个 `##` → 3 个分页。
- 「三、日志详情」区（`##` 标题含「详情」）内：
  - 每个 `###` 之前分页，**但紧跟本区 `##` 的第一个 `###` 不插**；
  - 每个「详情表」之前分页，**但该 `###` 下第一个详情表不插**；
  - 该区共 76 个分页。
- 3 + 76 = **79 个分页符**，与 org 实测一致。

### 8. 表格
- 判定：连续以 `|` 开头的行即一个表（**首行即表头，无需 `|---|` 分隔行**）。
- 统一：style=TableNormal、tblW=8800、居中、tblInd=1034、tblLayout=**fixed**、tblLook=01E0、
  tblCellMar 全 0、四边 single 边框 颜色 `DBDEE4` 线宽 0.75pt（sz=6）、文字**宋体 10.5pt**、**全部单元格不加粗**
  （日志表 c0/c1/c3 数据列按用户偏好不加粗，此为对 org 原“该 3 列加粗”的刻意偏离）；
  空单元格（含合并产生的续格）经 `normalize_empty_cells()` 补一个 宋体/10.5pt 的空 run（**不加粗**，与 org 空续格一致）。
  **单元格对齐按物理列分设（org 实测，易错！）**——见下方「单元格对齐规则」。
- **⚠️ 固定布局下列宽由 `tblGrid/w:gridCol` 决定，不是单元格 `tcW`**。python-docx 建表只给默认等宽
  gridCol，必须在每个表 `apply_table_style` 之后调用 `set_table_grid(table, widths)` 把 gridCol 宽度
  设成真实列宽，**否则宽列（如日志「内容」列）会被压成 1/4 宽 → 文字狂折行 → 整表变高溢出分页**。
  各类型 grid（实测 org）：
  - 类型 A 日志清单（时间/操作/内容/字数，4 列）：`[1726, 954, 5153, 967]`（时间列缩小，内容列加宽并加左右 80twips 内边距，操作/字数列不变）
  - 类型 B 横向环节分布（12 物理列、6 合并表头）：`[734, 733, 734, 733, 734, 733, 734, 733, 733, 733, 733, 733]`
    （6 组等宽，每组 2 列合并 ≈1467 twips；合并表头单元格 tcW 用 `[1467,1467,1467,1467,1466,1466]`）
  - 类型 C 时间分布（按周或按月）：首列「周」/「月份」，其余分桶标签；**列数随日期范围自动扩展**，
    渲染时由 `even_widths(ncol)` 把 8800 twips 均匀分配（不再固定 12 列 grid / tcW）。
  - 类型 D 日志详情（6 物理列、2 组合并发表头）：`[1467, 1467, 1467, 1467, 1466, 1466]`（6 列等宽）；
    表头合并单元格 tcW `[4401, 4399]`（各 3 列之和）；描述行第二列跨 5 列 tcW=sum(col1..5)=7333
- **单元格段前距按表格类型/行号分设**（org 实测，必须一致，否则行高不对）：
  - 日志：表头=127 / 数据行=13
  - 横向环节分布：127, 127, 155（末行略大）
  - 时间分布：全部=155
  - 日志详情：全部=127
  （实现见 `row_space_before(ttype, ri, nrows)`）
- **单元格内边距（tcMar）**：表格级 `tblCellMar` 设为全 0（紧凑布局），但以下列需单独设置单元格级左右内边距 80 twips（≈5pt），避免文字贴边框：
  - 日志清单表（类型 A）：内容列（c=2）所有单元格（表头+数据行）`left=80, right=80`
  - 日志详情表（类型 D）：描述列（span=5，跨5列的长文本行）所有单元格 `left=80, right=80`
  - 实现：新增 `set_cell_margins(cell, top, left, bottom, right)` 函数，设置单元格级 `tcPr/w:tcMar`，覆盖表格级默认值
- **单元格对齐按物理列分设（org 实测，极易被忽略）**：org 并非所有单元格居中。判定时必须遍历
  `tr._tr.findall(qn('w:tc'))` 物理元素读 `w:jc`/`w:vAlign` 才准——python-docx 对合并单元格的
  `row.cells` 视图会把合并列误报成 `None`，导致把「实际居中」错判成「左对齐」。规则（直接读物理 XML 确认）：
  - 日志表（4 列）：**表头 4 列全居中**（含 c2 内容列）；数据行 c0/c1/c3 水平居中、垂直居中，
    **c2 内容列水平 = `both`（两端对齐 JUSTIFY）、垂直继承（不写 w:vAlign）**。
    （注意：表头与数据行的 c2 对齐不同——表头居中、数据两端对齐，别混淆。）
  - 横向环节分布 dist（12 列）：**整表水平居中**（表头行、标签行（新增/修订…）、末行数字均居中）。
    ⚠️ **此点与 org 原样式不同**：org 原表头/标签行左对齐、仅末行数字居中；此处按**用户偏好**改为整表居中
    （用户 2026-07-28 明确要求“次数统计表第一行与第二行居中对齐”）。
  - 时间分布 weekly（列数动态）：全部列水平居中、**垂直继承（不写 w:vAlign）**。
  - 日志详情 detail（6 列）：**c0 标签列 + 短值列（span=1）水平居中、c0 垂直居中**；
    **描述列（跨 5 列的长文本，span=5）水平 = 继承（左对齐，不写 w:jc）、垂直继承**。
    ⇒ 规则按「合并跨度」判定：`halign = None if span == 5 else 'center'`，并非整表居中！
    描述列左对齐是 org 实测（之前误判成全居中，导致大量单元格对齐不一致）。
  - 实现：`set_cell_formatting` 新增 `halign`/`valign` 参数——`halign='both'`→JUSTIFY、`halign=None`→不写
    w:jc（继承左对齐）、`valign=None`→不写 w:vAlign（与 org「未设」单元格 XML 完全等价，渲染必然一致）。
    顶部常量 `ALIGN_LOG_H/V`、`ALIGN_DIST_H/V`、`ALIGN_WEEKLY_H/V`、`ALIGN_DETAIL_H/V` 定义各列对齐，
    由 `build_table` 各分支按起始列传入。
- 空单元格按 org 约定视为「与左侧非空单元格合并」（见 `merge_trailing_empties` / `merge_header_empties`）。
- 表内**不支持 markdown 加粗**：`**...**` 标记在表格单元格中**直接去除星号、不渲染加粗**（org 表格本无加粗）；
  仅 `<br>` 渲染为换行。注意 md 的周分布表数据行曾写成 `| **新增** | **5** | …`，转换后显示为“新增 / 5”（无加粗），与 org 一致。

### 9. 抑制「md 独有、org 没有」的自由文本
org 正文除封面字段 / 章节标题 / 表格 / 图表注记外**不含其它自由文本**。md 里多出的这些行在生成时**整行丢弃**
（`is_md_only_text`）：
- 每条日志详情前的 `【条目名】` 标号（`^【.*】$`）；
- 汇总统计区的 `说明：` / `说明:`（含 Markdown 引用块形式 `> 说明：…`，需先剥 `>`）；
- `按周分布`、`各阶段要点`；
- 周次列表 `- 第N周…` 子弹点（`^-\s*第\d`）。
> 注意：md 的 `说明：` 常以 `> ` 引用块出现，判定前必须 `re.sub(r'^>\s*','',s)` 剥掉引用符，否则会漏判而把
> 这段说明泄漏进生成文档。

### 10. 正文段落
- **markdown `**` 标记统一去除、不渲染加粗**（org 正文与表格均无 markdown 加粗，加粗仅由显式规则控制：
  封面标题 / 二级目录 `###`；日志表 c0·c1·c3 按用户偏好不加粗）；`[n]` 文献引用保持原样（纯文本）；`<br>` 渲染为换行。

### 11. 图表（内联数据驱动，无外部资源）
- 「所有日志时间分布图」的柱状图**不依赖任何静态图片**：`maybe_insert_chart()` 触发时调用
  `build_weekly_chart_png(md_path)`，先从 md 的时间分布表解析出分桶标签与新增/修订数值，再用 matplotlib（SarasaFixedSC 等宽中文字体）
  现画一张「日志时间分布图（按周/按月，合计 N 条）」中文柱状图（新增蓝 #2E75B6 / 修订橙 #ED7D31），保存到系统
  临时 PNG、嵌入后删除。
  - **表头识别（2026-07-29 改为按月）**：时间分布表首列须为「周」或「月份」，其后为分桶标签——
    按周为「第1周…第N周」（N 随日期范围自动扩展），按月为「YYYY年M月」（连续月份，含无数据月份）。任一形式只要
    首列是时间分桶标签且分桶列≥2 即被 `parse_weekly_table` 解析为 (labels, added, revised)。`build_weekly_chart_png`
    据标签是否含「年」自动切「按月/按周」标题与 x 轴字号。
  - 下接「新增/修订」两行，中间可能有 `|---|` 分隔行。
- 插入尺寸固定 15.24×6.0cm（≈2.54:1），故 `figsize=(6.0, 2.362)` 且**不用 `bbox_inches='tight'`**（否则裁白边改比例→拉伸变形）。
- 数据完全来自 md 表格：若日志条目变化导致表格数字改变，重跑转换器图表自动更新，**不会再有"图写死、表改了图没改"的隐患**。
- 解析兜底：表头与数据行之间可能含 markdown 分隔行，`parse_weekly_table` 显式向下搜索首个含「新增」的行作为数据起点，避免偏移取错行。
- **统计条数一律依据实际「新增+修订」重算（2026-07-28 新增）**：
  - 周分布表（weekly 类型）渲染时，其「**合计**」行的每个单元格都被 `build_table` 按 `新增[c] + 修订[c]` **实时覆盖**，不再照搬 md 里人工写死的「合计」行。即 md 的「合计」行数字即便与「新增/修订」不一致，Word 里也会显示正确的合计。
  - `parse_and_build` 在开头调用 `parse_weekly_table` 算出 `weekly_total = sum(新增)+sum(修订)`，正文段落若出现「合计 N 条」也按此自动替换（注：原 md 的「按周分布（单位：条，合计 77 条）」那句属 md 专有文本、在转换中被丢弃，故实际只在图表标题与表格合计行体现）。
  - **维护约定**：今后只改 md 的「新增」「修订」两行即可，Word 的「合计」行与图表标题会自动更新；md 里的「合计」行数字可保持原样，不影响 Word 输出。

## 实现要点 / 易错点（维护必读）

生成结果与 `_org.docx` 逐页一致，关键在于绕开以下 OOXML 坑，改代码时**切勿回退**：

1. **pPr / rPr 子元素必须按 schema 顺序插入**。手动 `OxmlElement('w:jc')` 后 `ppr.append` 会把它
   放到 `w:ind`/`w:spacing` **之后**，违反 CT_PPr 顺序（…spacing, ind, …, jc…），Word 打开即**丢弃 jc**，
   标题/封面就不居中了。同理 `w:rFonts` 必须在 `w:b`/`w:sz` **之前**（紧接 rStyle）。
   → 一律改走 python-docx 原生 `paragraph_format.alignment / left_indent / space_before /
     line_spacing` 与 `_apply_cjk` 里 `rpr.insert(idx, rfonts)` 的正确下标插入。
2. **表格不要重复 `tblW`**：`doc.add_table()` 已建一个 `w=0 type=auto` 的默认 `tblW`。必须
   `find` 复用它再 `set`，不能 `append` 第二个，否则出现两个 `tblW` 属 schema 非法，Word 可能取
   `w=0` 把表格宽度压成 0（表格看起来“没了”）。
3. **中文（eastAsia）字体**：用 `rfonts.set(qn('w:eastAsia'), font)` 显式写，不能只靠
   `run.font.name=`（那只设 ascii/hAnsi，中文会回退到西文字体）。
4. **🔴 固定布局下列宽 = `tblGrid/gridCol`，不是 `tcW`**（最重要的一条）：
   设 `tblLayout=fixed` 后，LibreOffice/Word 用 `<w:tblGrid>/<w:gridCol>` 的宽度分配列，
   **完全忽略**单元格 `tcW`。python-docx 建表只给默认等宽 gridCol（如 4 列表 `[2675]*4`），
   若不再调用 `set_table_grid()` 覆盖，宽列会被压成等宽 → 内容列过窄 → 狂折行 → 整表 2~3 倍高、
   溢出分页。→ 每个 `build_table` 分支在 `apply_table_style` 之后**必须** `set_table_grid(table, widths)`。
5. **🔴 `docDefaults` 去冗余**：python-docx 默认模板在 `w:docDefaults/w:pPrDefault/w:spacing` 注入
   `after=200 line=276 lineRule=auto`。`after=200` 让每个单元格/段落段后多 200twips，累积使整文档多约 4 页。
   → `neutralize_doc_defaults()` 把 `after` 设 0 并删除 `line/lineRule`（回到 natural single）。
6. **🔴 标题 1 样式 `space_before`**：默认 Heading 1 带 `space_before=480`，非首个 `##` 若只设行高不设
   段前会继承 480 而下沉。→ `neutralize_heading1_style()` 把标题 1 的 `before/after` 归 0、字号 26。
7. **表格判定**：连续以 `|` 开头的行即一个表（首行当表头，**无需 `|---|` 分隔行**）——这是 org 的真实
   行为（本 md 共 85 个表块：6 日志 + 1 横向分布 + 1 按周 + 77 详情）。
8. **每类型单元格段前距不同**（见规则 8）：用 `row_space_before(ttype, ri, nrows)` 按类型/行号返回，
   日志数据行 13twips、表头 127twips 等，错设会让行高不对、分页偏移。
9. **md 独有自由文本必须丢弃**（见规则 9）：`【…】`/`说明：`/`按周分布`/`各阶段要点`/周次 bullet，
   且 `说明：` 可能以 `> 说明：` 引用块出现，判定前先剥 `>`。
10. **核对口径**：用 `docx` 读取属性时必须用 `qn('w:xxx')`（Clark 记号 `{ns}xxx`），不能用
    `'{%s}%s'%(W,'w:xxx')` 这种错误拼接（会得到 `{ns}w:xxx`，永远读不到）。
11. **分页规则**（见规则 7）：每个 `##` 分页；详情区内每个 `###`/每个详情表分页但首者除外，共 79 个分页符。
12. **单元格内边距（tcMar）**：表格级 `tblCellMar` 全 0，但内容列/描述列需通过 `set_cell_margins()` 设置单元格级左右 80 twips 内边距。
    注意：`set_cell_margins` 操作的是 `tcPr/w:tcMar`（单元格级），会覆盖 `tblPr/w:tblCellMar`（表格级）的默认值。

## 已知限制 / 注意事项

- **🔴 与 `_org.docx` 的两处刻意差异（用户偏好，非 bug）**：
  1. **日志表数据行 时间/操作/字数 三列（c0/c1/c3）不加粗**——org 原对这 3 列加粗；2026-07-28 用户
     明确要求去掉，故生成文档该表整表无加粗。
  2. **次数统计表（dist）整表居中**——org 原表头/标签行左对齐、仅末行数字居中；2026-07-28 用户要求
     “第一行与第二行居中对齐”，故改为整表居中。
  > 若日后需要**严格还原成与 org 逐字一致**，把 `build_table` 的 log 分支 `bold=False` 改回
  > `bold=(c in (0,1,3))`、dist 分支 `halign='center'` 改回 `halign='center' if is_last else ALIGN_DIST_H[c]`
  > 即可（代码注释已标明位置）。
- **周分布柱状图已完全数据驱动**：由 `build_weekly_chart_png()` 从 md 周分布表实时生成，
  **不打包任何静态图片**。若日志条目变化导致表格数字改变，重跑转换器图表自动更新，无"图写死"风险。
  这是本 skill 与「纯文本/表格」转换的唯一曾非自动化环节，现已闭环。
- **生成文档页数可能比 `_org.docx` 多 1~2 页属正常**：当前研究日志.md 持续更新，内容比 org 基线多
  （实测多约 450 字符），重新生成会如实反映**当前 md**，这正是本 skill 存在的意义；与 org 的少量
  文字/页数差异是 md 演进所致，**非排版 bug**。逐页像素差 avg≈6 主要来自 LibreOffice 用替代字体
  渲染宋体，用 Word 打开会进一步贴近 org。
- **🔴 md 条数 / 章节改变时，word 会自动对应调整（设计目标，非 bug）**：
  解析器完全**数据驱动**——`parse_and_build` 顺序扫描 md 行，`build_table` 依据表头结构
  （`detect_table_type`）判定类型并生成，无任何硬编码的条数 / 表格计数。因此：
  - md 给某日志表**多一行** → 该日志表自动多一行；
  - md 在「三、日志详情」里**新增一个 `###` 小节（含详情表）** → word 自动多一张详情表，并依分页规则
    独占一页（已用受控测试验证：原 85 表 → 86 表，且新增日志行、新增详情表内容均正确进入生成文档）；
  - 新增其它章节（`##`）/ `###` / 表格同理自动反映。
  维护时注意：**不要为“凑 org 的表数”而写死任何计数**；改动解析逻辑后，用「加一行 / 加一个小节」的
  受控测试确认动态增减仍正确。
- 转换脚本不会改动源 `.md` / 源 `.docx`；只有显式运行且指定输出（默认即覆盖同名 docx）时才会写出
  Word 文件。
